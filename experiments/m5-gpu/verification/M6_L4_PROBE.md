# M6 L4 recovery probe

Parent checkpoint implementation: `00966ec2d51eb2a52c485782a306b70cb2f8a1f8`. This predeclared smoke test uses the Rust M6 process fixture, one NVIDIA L4, FP32, TF32 disabled, the T sampler and seed 19. It supplies 53 synthetic integer tokens, context 8, batch 2, one layer, hidden width 8, two heads and FFN width 16. AdamW runs for four updates with one warmup update and cosine decay.

The control process runs four updates continuously. The interrupted process publishes after step 2, executes an unpublished third update and signals readiness. The supervisor kills that process with SIGKILL. A fresh process restores step 2, immediately republishes it for a byte-for-byte comparison, then continues to step 4.

**Acceptance fixed before GPU execution.** Immediate restore and republication must preserve every checkpoint byte. Each resumed trajectory must use exactly the control's input and target windows, cursor, RNG state, learning rate and step. Final checkpoint metadata must match exactly. Report bitwise equality for final images and per-step losses. For each finite parameter, first moment, second moment and loss, the maximum permitted individual difference is `1e-5 + 1e-3 * abs(control)`. This diagnostic ceiling is the existing M5 FP32 reference threshold, chosen before observing the L4 result. No observed difference is rounded away for the bitwise comparison. CUDA gradient reductions can vary between independent runs. A four-update pass establishes only this fixture's behavior.

The session is requested once after the native Ubuntu-24.04 CPU checks, CUDA compilation, binary/runtime rehearsal, package verification and budget approval. All Rust compilation is local. The Colab session executes the prebuilt fixture and transfers a small results archive. The time budget starts at the allocation request and reserves 130 seconds for cleanup. An active rate projecting above the approved CU ceiling causes immediate release. The reported CU balance is rounded and its update can lag. Inventory, rate, release and post-release balance are verified separately from model success.

Publishing time includes checksum readback and directory sync. Restore time includes fresh model construction and device synchronization. Each worker's host high-water mark is sampled from Linux VmHWM at roughly 20 ms intervals. Device-wide VRAM is sampled at 100 ms. These observations include runtime overhead and do not measure allocator-only memory or LIV-scale throughput.
