# M6 — Training reliability and checkpoint recovery

M6 adds recoverable Transformer training in the existing Rust experiment workspace.
The scientific question and historical M5 runs retain their original inputs, schedules and results.
Development started at `0ff55235dd802678c785e194c7cb9adf8481a530` on `codex/m6-training-recovery`.
The [verification record](../../experiments/m5-gpu/verification/m6-recovery.txt) identifies the tested source files and reference environment.

## What failed in M5

The first completed A training run stopped in evaluation. Global token-order addition and addition of per-domain FP64 sums round differently. The old absolute NLL difference limit of 1e-9 rejected an otherwise consistent score. The existing fix uses
`abs(global - grouped) <= 1e-12 * max(1, abs(global), abs(grouped))`. The rule has an absolute floor near zero and scales with the total above one. It is an empirical reconciliation bound for these nonnegative losses. It cannot distinguish discrepancies smaller than the bound or guarantee acceptance of every possible summation order.

M6 retains this formula and M5's sorted domain reduction. On the 800,000-target synthetic regression the measured sums were 4,990,660.100032396 and 4,990,660.100032379. Their difference of 1.67638e-8 exceeds the old limit and lies below the current limit of about 4.99e-6. The pilot report records a separate 8.38e-9 observation. Tests also cover zero, values immediately inside and outside the absolute and relative limits, NaN, infinities, finite sums that overflow, missing report categories and one-unit counter errors. The code requires finite sums and BPB, checked split offsets and exact integer reconciliation. The independent batched scorer must match token and represented-byte counts exactly and BPB within its existing 1e-4 cross-path threshold.

A's 2,000-update state was recovered and reevaluated under the fix. C then completed 2,000 updates. Final validation BPB was **2.572964850 for A and 2.597469229 for C**. This single paired seed favored A by 0.024504380 BPB with different raw-byte exposure. Both final TEST scores have been seen. Earlier failed launches, the failed A aggregation and its checkpoint remain part of the record. [Pilot result, hashes and accounting](../../experiments/m5-gpu/provenance/m5-a-c-pilot-20261009T154700Z/PILOT_RESULT.md).

## Compatibility and operator entry points

| Artifact | Reader and purpose |
|---|---|

| Extended M5 `latest.resume.safetensors` | `train-extended` uses the v1 reader with the original frozen plan and metrics log. This image already included weights, first/second moments, counters, schedule, RNG, cursor and input identities. Its tensor hash did not cover the continuation metadata. For archive recovery verify the trusted external file digest as well. |
| M6 `training-v2/step-<20 decimal digits>.ptc` | `train-recoverable` creates or continues a v2 run. It uses the extended runner's sampler, loss, optimizer, evaluation and checkpoint cadence. A run directory belongs to one format. |

For a separately authorized training run the binary syntax is
`packtok-m5 train-recoverable CONFIG DATA OUT VARIANT REGIME SEED APPROVAL_REFERENCE`.
Use a dedicated, durable local output directory and immutable prepared data. Reinvoke with the same arguments and output to recover. The production entry still checks the matching approval environment, frozen configuration and inputs, and requires an L4. M6 verification uses a private tiny CPU fixture for the same runner body. There is no CPU substitution in the production command. The 20k and 30k schedules have different frozen config hashes and different cosine trajectories. Migrating a run between them would be a new training protocol.

## State and byte format

Pinned `candle-nn 0.9.1/src/optim.rs` keeps AdamW's per-variable moments and `step_t` private. Its public parameter getters/setters expose hyperparameters. It provides no optimizer state import/export. M6 reuses PackTok's existing named `ResumableAdamW`. The differential unit test checks an update against Candle. Both moments are detached between updates, and an update error invalidates the optimizer for further updates or publication until restored.

The image is one binary file, in the following order.

1. Eight ASCII bytes `PKTRN002` and the little-endian u32 byte length of the UTF-8 JSON header, capped at 16 MiB.
2. A typed header with model architecture, batch size, seed, variant/regime, train sequence length and sampler bounds, model/backend precision, ordered parameter names and dimensions. It stores SHA-256 for the frozen training config, corpus manifest, tokenizer artifact, mapping file, effective tokenizer (artifact concatenated with the mapping), and actual TRAIN sequence. The config hash also binds the individual split hashes. The runner validates both tokenizer identities and all six prepared sequences before training. The input files must stay immutable for the lifetime of the job.
3. The same header contains AdamW LR, betas, epsilon, weight decay, warmup, decay rule and schedule length. One completed-step counter is authoritative for training, optimizer bias correction and the next scheduled LR. The xorshift64 (13/7/17) state and sampler cursor determine the next input. T counts target positions and replays the seeded draws to validate RNG and count represented bytes. B stores the next target token inside the matched interval and validates the step, byte-range cursor, schedule capacity and unchanged RNG. M5 uses no dropout. Initialization randomness is superseded by the saved parameters. Gradient accumulation is fixed at one, with no pending gradients at publication.
4. The header also carries accumulated training, pipeline and wall seconds and sampled peak VRAM. The experiment runner binds each nonzero checkpoint to the length and SHA-256 of the committed metrics journal prefix. Library users of model/optimizer recovery can omit the external journal. The CPU/CUDA backend and FP32 math contract are explicit. The CUDA run requires TF32 override zero. JSON floating-point decoding uses round-trip precision.
5. Payload records follow sorted parameter name order. For each parameter write its weight, first moment and second moment in that order. Each tensor is row-major FP32 little endian in the declared shape. Nonfinite values and negative second moments are rejected.
6. A 32-byte binary SHA-256 digest covers every preceding byte. Restore checks magic/version, bounded header, expected run identity and schedule, step, sampler bounds, backend, precision and layout. It constructs the model privately, verifies the bytes it actually consumes, checks the trailer and requires EOF before returning usable state. The digest detects corruption. Authenticity against deliberate replacement requires a trusted external receipt.

## Publication and recovery

The runner holds an OS file lock for its v2 output. At a boundary it flushes and syncs the journal, seals its prefix, streams a unique pending file, syncs that file and checks its digest by readback. A same-directory hard link publishes the image under an immutable step name with no overwrite. A directory fsync makes the name durable on the tested Linux filesystem. File and directory sync guarantees depend on the filesystem and storage stack. Readback can come from the OS cache. A writer returning an error discards its own temporary. An abrupt kill can leave a pending name. The next locked runner removes abandoned writer temporaries. The library publication API requires caller coordination for shared runs. A duplicate step cannot overwrite a committed image.

Recovery selects the highest published step. An invalid newest generation fails visibly. To recover from a damaged image, preserve the original run, copy an earlier verified generation into a fresh `OUT/training-v2/` and copy its matching `metrics.jsonl` into `OUT/`. The journal may contain later observations. On restart the runner checks the committed prefix and archives the original log before rewinding excess bytes. A missing, truncated or changed committed prefix stops the experiment runner. Checkpoint zero precedes the journal. Standalone training-state restore does not depend on telemetry for the next optimizer update. A retried final report retains the originally measured time and verifies the scientific fields.

All published generations remain available. Capacity planning must cover the number retained plus a pending write. Archive older verified generations together with their journals under the run's provenance policy. For one billion FP32 parameters one generation would contain **12,000,000,000 payload bytes** for weights and two moments, plus framing and metadata. This is arithmetic, not a measured LIV image. The writer transfers at most 65,536 elements per chunk. CUDA views are compacted before host transfer because Candle can copy an entire backing storage for a narrow view. The reader builds at most one parameter-sized host value vector at a time in addition to the live model and optimizer. No v2 path serializes all tensors into one in-memory byte vector.

## Verification and independent review

The fresh-process comparison uses one layer, hidden 8, two heads, FFN 16, context 8, vocab 512, batch 2, seed 19, 53 synthetic tokens, FP32 and one Rayon thread. Four AdamW steps include warmup and cosine decay. The interrupted case publishes at steps 1 and 2, executes another unpublished update, then is killed by the parent each time. A fresh child continues to step 4. The test compares actual inputs and targets, each loss and LR by bit pattern, cursor, RNG, final step and the digest of the entire final image. It covers T and B, including B's four-target final batch. The separate runner fixture exercises journal rewind, original scientific reports, rejected missing/truncated/altered logs, exclusive writer locking, format exclusion, repeated finalization and real nonzero timing. The Linux write-failure fixture interrupts publication using a file-size limit and resumes from the previous image. Format tests exercise truncated headers/payloads/trailers, corruption of metadata and payload, unknown version, trailing bytes, invalid tensors, failed updates, wrong input hashes and mismatched configurations.

| Independent reviewer via local agy | Findings and resolution |
|---|---|
| Gemini 4 Neon High — architecture | Confirmed v1's whole-image RAM amplification, unprotected metadata and journal/checkpoint durability window. V2 streams, covers both metadata and payload, and binds the synced journal. Its B schedule/cursor checks and replay protect sampler state. Proposed GPU evaluation and corpus speedups are separate experiments. |
| Gemini 4 Hydrogen Medium — regressions | Identified the nondeterministic report duration on retry, B cursor underflow and missing repeated/restarted process coverage. Added targeted fixes and tests. Per-update loss checks and publication-time finite tensor checks protect the last verified generation. Gradient diagnostics retain the frozen cadence. |
| Claude Sonnet 5.5 Medium — final implementation review | Identified silent loss of metrics history, temp-file accumulation and insufficient coverage of the runner around the serializer. Added journal prefix checks, cleanup under the writer lock and a real runner-body recovery test. Added a bounded worker lifetime and a size precondition on the Linux fault injection. Tested the actual A/C v1 images. Different frozen plans already have different identities. |

The reviews used sandboxed plan mode and isolated source copies with read-only analysis. The first Gemini invocations received no piped sources; subsequent requests supplied exact snapshot filenames. No external agent modified the working tree. No Opus escalation was needed.

## Reproduction

Both workspaces passed formatting and Clippy with warnings denied. The root
workspace passed 135 tests. The isolated suite passed 38 unit tests and four
integration test entries, including the subprocess worker. The separately
enabled archive test restored both original 2,000-step pilot images. The
replayed sampling/loss traces and complete final checkpoints matched in both
regimes. Full fixture digests and the serial rerun are in the verification record.

Two development gates initially failed. Rust 1.100 Clippy flagged a fixed-width
byte decoder, which now uses typed four-byte chunks. The first compile of the
runner regression rejected a JSON fixture macro expression; parenthesizing the
arrays fixed the fixture. The first native staging directory under WSL
`/tmp` disappeared between invocations. Final gates used a persistent native
directory and the previously prepared local sequences. These failures precede
the passing gates recorded below.

Use local Ubuntu-24.04 on an ext4 working directory with the locked dependencies and existing prepared inputs. The root suite uses Rust 1.85.0. The isolated Transformer suite was built with Rust 1.100.0. Run the following from the project root.

```sh
cargo +1.85.0 fmt --all --check
cargo +1.85.0 clippy --offline --locked --workspace --all-targets -- -D warnings
cargo +1.85.0 test --offline --locked --workspace
cd experiments/m5-gpu
cargo +1.100.0 fmt --all --check
cargo +1.100.0 clippy --offline --locked --all-targets -- -D warnings
RAYON_NUM_THREADS=1 cargo +1.100.0 test --offline --locked --all-targets -- --nocapture
cargo +1.100.0 test --offline --locked --doc
cargo +1.100.0 test --offline --locked --test recovery -- --test-threads=1 --nocapture
```

The historical compatibility test separately reads the two archived pilot images from a directory containing `A/latest.resume.safetensors` and `C/latest.resume.safetensors`. Set `PACKTOK_M5_PILOT_RESULTS` to that directory, then run `cargo +1.100.0 test --offline --locked --test recovery historical_pilot_images_restore_on_cpu -- --ignored --exact`. It verifies the published file hashes, loads both sets of weights and moments on CPU and checks 2,000 steps, 4,096,000 sampled positions and the expected RNG. It does no forward or backward pass.

## Limits and next milestone

Bitwise parity is verified on the declared CPU fixture. CUDA atomic gradient reductions, kernel/library versions and parallel math can affect later updates even when the restored state bytes are exact. M6 establishes no CUDA trajectory tolerance, crash survival on remote storage, multi-host coordination guarantee, actual billion-parameter throughput or disk high-water mark. The current M5 model construction limit remains 128 million parameters. No GPU, Colab units, corpus download or full-model CPU training was used.

The next milestone should measure recovery overhead and post-resume divergence on a separately budgeted small GPU run. Freeze the backend, numerical acceptance criterion, storage budget, and paired trajectory before launch. Measure checkpoint write/restore throughput, peak host/device memory, restart time and retained bytes at increasing representative tensor sizes before changing the M5 model limit for LIV-1B.
