# M7 — LIV Data Engine and initial training

M7 implements `packtok-m7` in the isolated Transformer workspace. The code is based on M6 commit `7b4df8f59ba2c06e5ee2122bf136638f40f7e983`. The production path reuses PackTok's Flat BPE trainer, lexical-v1 factorized trainer, byte-exact codec, model ID mapping, Candle Transformer and M6 recovery file. The root Rust 1.85 workspace remains independent of the data engine and CUDA.

## Run the local seed experiment

Use Ubuntu-24.04 on a native filesystem. The example assumes a fresh output directory and the archived source files described in the [source ledger](../../experiments/m7-data/SOURCES.md).

```sh
root="$PWD"
cached="$HOME/projects/PackTok/experiments/m5-gpu/data/sources"
work="$(mktemp -d "$HOME/tmp/packtok-m7-repro-XXXXXXXX")"
mkdir "$work/raw"
for id in 100 145 766 2403 5323 24782; do
  ln -s "$cached/pg$id.txt" "$work/raw/pg$id"
done
cargo +1.100.0 build --offline --locked --release \
  --manifest-path experiments/m5-gpu/Cargo.toml --bin packtok-m7
bin="$root/experiments/m5-gpu/target/release/packtok-m7"
"$bin" build experiments/m7-data/sources-local-v1.json "$work/raw" "$work/dataset"
"$bin" verify "$work/dataset"
"$bin" tokenize "$work/dataset" "$work/tokenized" 262144
"$bin" verify-tokens "$work/dataset" "$work/tokenized"
export RAYON_NUM_THREADS=1
"$bin" train-cpu "$work/dataset" "$work/tokenized" "$work/A" A 96
"$bin" train-cpu "$work/dataset" "$work/tokenized" "$work/C" C 96
"$bin" train-cpu "$work/dataset" "$work/tokenized" "$work/restart-A" A 40
"$bin" train-cpu "$work/dataset" "$work/tokenized" "$work/restart-A" A 96
cmp "$work/A/metrics.jsonl" "$work/restart-A/metrics.jsonl"
cmp "$work/"{A,restart-A}/training-v2/step-00000000000000000096.ptc
```

## Streaming and integrity

- The version-1 JSON catalog pins source group, split, language, extraction format, byte length, SHA-256 and the human license decision and its evidence. Ingest reads a snapshot of the approved catalog. It orders by train, validation, test, then ASCII source ID and input row. An author or other declared source group belongs to one split throughout the catalog. SHA-256 checks before and after processing guard against changed raw files. Keep the cache immutable while publishing.
- With an approved HTTPS URL and explicit byte cap, `fetch CATALOG CACHE SOURCE_ID MAX_BYTES` locks the cache slot, resumes a partial file via curl and limits local writes to the pinned length. HTTPS transport uses the system curl and its TLS trust. Rust owns validation, journaling of the partial via its length, publication and integrity. Full length and SHA-256 must match before a no-overwrite hard link publishes the cache entry. Oversized or failed full-length partials are held under `.bad-*`. Unpublished temporary data stays outside Git. Recovery is tested with an interrupted transport double. Real remote range support depends on the source server.
- Inputs are whole UTF-8 documents, archived Gutenberg books with explicit start/end markers, or bounded JSONL objects containing `text`. The per-document and raw JSONL-row cap is 8 MiB. Longer records are drained with bounded buffers. The quality gate rejects invalid UTF-8, controls other than TAB/CR/LF, recognized email addresses, labeled phone numbers and DE IBAN-shaped strings. Language is a fixed DE/EN stopword heuristic on the first 4,096 alphanumeric words, with 24 words minimum, an expected-language count of at least three and a margin of two. It uses no held-out statistics. Contact screening and language ID can yield both false negatives and false positives. Names, unlabeled numbers, obfuscated contact details, dialect and code-switching require further review.
- Redb 3.1.0 provides a disk-backed index with a 32 MiB configured page cache. It was added inside the isolated workspace because the original corpus trainers take in-memory input. The index tracks raw SHA-256, normalized lowercase word-sequence SHA-256, and three-word-shingle SimHash with four 16-bit bands and Hamming radius three. Near matching uses at least 32 words. Cross-split passage detection uses minima of 16 consecutive 12-word shingles, with rightmost ties. A shared run of at least 27 normalized words is detectable under this fingerprint rule. Hash collisions and common passages can reject valid documents. Paraphrases, shorter partial overlaps and shifts that change word tokenization can pass. A detected conflict drops the later document and records the reason and byte count. It never moves documents across splits. The larger word sets and buffers are bounded by a document, while the index grows on disk. Regex 1.12.3 compiles the fixed contact rules.
- JSONL data shards rotate at 64 MiB or on split boundaries. Output is staged in a unique sibling directory and published after file verification, sync and atomic rename on Linux. Manifests bind extraction digests, source attrition and shard sizes, records and hashes. Verify checks the published manifest and input order, source split and counters. It does not infer license terms from arbitrary files. The dedup index is rebuildable and omitted from final data. M7 keeps payloads outside Git.
- Tokenizer training reads only train shards. It takes a source-balanced deterministic prefix sample with a caller-provided cap from 1 KiB through 8 MiB. It preserves UTF-8 boundaries, with a separator byte per sampled record. Prefix sampling can overrepresent opening matter and repeated leading structure. The existing trainers remain in-memory over that bounded sample. The default budgets are 512 slots and minimum pair frequency two for both variants. A regression changes held-out text and compares the artifacts and mappings byte for byte.
- The encoder operates in 64 KiB UTF-8 chunks aligned to whitespace when found in the last 4,096 characters of a chunk. Each chunk round-trips through the existing tokenizer and mapping. The format `LIVWIN02` starts with eight magic bytes. Its 73-byte records contain a count in the low seven bits of the first byte and a chunk-start flag in the high bit, then nine little-endian u32 ID/length pairs with zero padding. Subsequent windows overlap one token and each chunk resets context. Verification checks overlap, SHA-256, sizes, token totals, scored bytes and the train sample receipt. Training indexes windows on disk and only places one batch in tensors. This first format trades storage for simple verified random access.

## Training probe

A and C use the existing one-layer 9,360-parameter FP32 Transformer, seed 19, context eight, batch one, 96 AdamW updates, LR 0.008, warmup four and cosine decay. A uses Flat BPE, C flattened lexical-v1 IDs. Xorshift64 selects a disk window. Short tails advance to the next full window. Each variant consumes 768 target positions, with raw-byte exposure recorded per step. The initial and final held-out probes use the same up-to-512-byte prefix per document for both tokenizers, up to eight documents. The first token of each prefix is excluded from loss and its byte count. The test split is encoded for integrity and remains unscored. These archived texts overlap earlier M5 source material and are suitable for pipeline verification.

The runner checks all gradients and loss, reports byte-normalized scores and generates 24 greedy tokens. It publishes a step-zero M6 image, then checkpoints every 32 completed steps and at the requested endpoint. The saved journal prefix binds the window, RNG, LR, loss and represented bytes to the committed checkpoint. Recovery archives the previous journal when removing an uncommitted suffix.

## Scaling targets

| Target | Evidence or gate |
|---|---|
| 100 MB | Synthetic opt-in `tests::scale_100_mb` creates about 100 MB JSONL and runs build, both tokenizers and integrity checks. Authentic seed data are smaller. |
| 1 GB | Pilot with approved pinned sources. Measure accepted language/domain share, filter attrition, effective document length, index growth, RAM, stream expansion and verified I/O. |
| 10 GB | Scale on representative approved shards after the 1 GB run. Measure hot SimHash bands, checkpoint restart and contention. |
| 100–150 GB | Long-term target. Reserve storage for original inputs, staging, deduplication and both encoded variants. Evaluate packed storage before freezing the long-range layout. |

On the authentic seed the two window streams plus small metadata take around 60.6 MB per 6.08 MB of retained text. This is about 10× before the raw cache, index and staging. A linear budget using this observation puts 100–150 GB of retained text at roughly 1–1.5 TB for both token streams alone. Composition changes the ratio. The engine is bounded by record size and disk, and benchmarks above RAM remain pending. The report records the independent CPU and BPE tests, preserved initial failures and the separately budgeted CUDA plan.
